# Android APK builds

The Android application is **Viper**, package ID `com.viper.business`, min SDK 24, target/compile SDK 36. It bundles the React client with Capacitor. The APK runs entirely on the phone, without Node or a remote server. All amounts use PKR.

## GitHub Actions

Push the changes to `main`/`master` or manually run **Android APK**. Pull requests also run the workflow. It uses Node 22 and Java 21, runs type checks and API regressions, builds the web assets, syncs Capacitor, runs Android lint, and uploads **Viper-debug-apk**. Nothing in the workflow installs the app on a user's phone.

A separate job runs an emulator matrix for Android API 35/36, gesture/three-button navigation, a tall display cutout, and portrait/landscape. These instrumentation tests check the native inset bounds of invoice controls, plus empty setup, offline invoice/payment/return/reopen flows and Android print/share dialogs. Web UI checks cover invoice safe-area spacing; device matrix results must be reviewed in Actions before release.

The default artifact is a debug APK for testing. For a signed release with a consistent update key:

1. Set repository variable `VIPER_SIGNED_RELEASE` to `true`.
2. Add repository secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD` for your existing release keystore.
3. Run the workflow on a trusted branch. **Viper-release-apk** contains the signed release APK. Release signing does not run on pull requests. Keep the keystore for all future updates.

Release version codes follow the workflow run number. If an existing installation uses a higher version code or a different signing key, adjust the versioning/key before distributing an update. Debug keys generated by clean runners may differ between builds, so use the signed release path for ongoing distribution.

## Offline data

A new install starts empty and opens Business Profile setup. Business data is saved in app-private SQLite with full synchronous transactional writes, versioned compare-and-save protection, and five recovery snapshots. Success is reported only after the native write commits. Corrupt data is reported rather than replaced. No backend URL, access token or internet connection is required.

Export backups from Settings and share them to a safe location. Uninstalling or clearing app data removes the local database; automatic Android cloud backup is disabled. Restore validates the entire backup before replacing data. Recovery snapshots are on the same device and do not replace exported backups.

Currency is PKR throughout the UI, printed invoices and exports. Changing denomination preserves existing numeric values; it does not convert historical INR amounts. Indian UPI QR payment requests are disabled. Existing tax calculation fields are retained for compatibility; configure the rates appropriate for your business.

## Status bar, cutouts, keyboard and navigation buttons

- The viewport uses `viewport-fit=cover` and keyboard resizing.
- `MainActivity` enables Android edge-to-edge; Capacitor `SystemBars` uses native inset handling. Older WebViews receive native padding; newer WebViews provide safe-area values to CSS.
- App content, the mobile menu, sidebar and modal overlays reserve top/left/right/bottom safe areas.
- Modal bodies scroll independently while action footers stay above the bottom safe area. Forms resize with the keyboard.
- System icon colors track light/dark theme. The status bar and Android navigation controls remain visible.
- Android Back closes a dialog or menu, returns to Dashboard, then minimizes the application. It does not discard POS drafts during navigation.
- Android printing opens the system print dialog; exports/backups use the Android share sheet. No broad storage permissions are requested.

Implementation follows [Capacitor System Bars guidance](https://capacitorjs.com/docs/apis/system-bars), including the older-WebView inset fallback. Browser simulations are useful evidence but do not replace the native emulator matrix or a physical-device check.

## Local checks (without installing)

```powershell
npm ci
npm run type-check
npm test
npm run build
npx cap sync android
# Java 21 and an Android SDK with platform 36 are required:
cd android
.\gradlew.bat :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
```

No `adb install` or device launch is necessary to compile and lint. Local acceptance runs use a dedicated Android 16 emulator with network disabled. No physical phone is installed or modified. Review the full API 35/36 navigation-mode matrix in GitHub Actions and smoke-test the signed artifact on your target phone before distribution.
